# 刘运昆的团队编程体验

* 学号：102301225
* 负责模块：团队博客撰写

## 我完成的具体工作

在本次项目中，我负责部分工作：
一是作为**代码审查者**，看懂检查各位组员提交的代码；
二是负责**团队博客的撰写**，将项目开发过程中的技术细节、踩坑经验与架构设计整理成文，对外输出。

## 遇到的问题与解决方法

**代码审查工作远比想象中耗时。** 我需要快速理解大家编写的不同模块（从前端 JS 到后端 Python），并检查边界条件。比如在审查前端代码时，我要特别注意 `parseFloat` 可能引发的精度陷阱；在审查后端时，要留意 Python 中 `bool` 作为 `int` 子类可能导致的类型校验漏洞；还要检查各个接口的返回值格式是否满足统一标准。

**撰写博客时，最大的挑战是如何“降维”表达。** 如何把类似 `os.replace` 原子写盘、`RLock` 防并发写覆盖这样生涩的技术点，转化为通俗易懂的团队经验分享，这需要反复斟酌语言，寻找合适的比喻和案例。

## 团队协作体验

通过“检查代码”和“写博客”，我被迫跳出了“只写自己那一亩三分地代码”的局限，获得了更宏观的系统视角。检查别人的代码让我见识到了不同的编码习惯，也让我更深刻地理解了接口对齐和防御性编程的必要性。而撰写博客则是对整个项目知识的重新梳理和沉淀。

## 收获与改进

我发现，代码审查是保障软件质量的最后一道防线，而一篇好的技术博客不仅是团队成果的展示，更是对自身逻辑表达能力的一次绝佳锻炼。
